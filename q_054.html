Question 54 / 361

Your team needs to make sure that their backend database can only be accessed by the frontend application and no other instances on the network. How should your team design this network?

  • A. Create an ingress firewall rule to allow access only from the application to the database using firewall tags.
  • B. Create a different subnet for the frontend application and database to ensure network isolation.
  • C. Create two VPC networks, and connect the two networks using Cloud VPN gateways to ensure network isolation.
  • D. Create two VPC networks, and connect the two networks using VPC peering to ensure network isolation.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Poprawna odpowiedź: A

1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:
Wymaganie: Baza danych (backend) może być dostępna wyłącznie dla aplikacji frontendowej. Żadne inne maszyny w sieci VPC nie mogą mieć do niej dostępu:
- Utworzenie reguły zapory sieciowej dla ruchu przychodzącego (ingress firewall rule) zezwalającej na dostęp do bazy danych wyłącznie z tagów sieciowych przypisanych do frontendu (A): W GCP reguły zapory sieciowej mogą filtrować ruch nie tylko po adresach IP, ale również po tagach sieciowych (network tags) lub kontach usługowych (service accounts). Przypisanie tagu `frontend` do maszyn aplikacyjnych i tagu `database` do maszyn bazodanowych pozwala na stworzenie reguły: "zezwól na ruch na porcie bazy danych tylko wtedy, gdy źródłem jest tag `frontend`". Jest to rozwiązanie elastyczne, bezpieczne i zgodne z zaleceniami GCP.

2. Wyjaśnienie niepoprawnych odpowiedzi:
- B. Utworzenie różnych podsieci (subnets): Podsieci w tej samej sieci VPC w GCP nie zapewniają izolacji sieciowej – domyślnie ruch między podsieciami w ramach tej samej VPC jest w pełni dozwolony i routowalny. Sama zmiana podsieci bez reguł firewall nie blokuje dostępu.
- C. Dwie sieci VPC połączone przez Cloud VPN: Połączenie dwóch sieci przez VPN umożliwia pełen routing między nimi. Jest to rozwiązanie niezwykle skomplikowane i generujące duże koszty, które nie zastępuje precyzyjnego filtrowania ruchu na poziomie maszyn.
- D. Dwie sieci VPC połączone przez VPC Peering: Podobnie jak w C, peering sieci VPC łączy je na poziomie routingu. Bez reguł firewall maszyny z jednej sieci mogłyby bez przeszkód łączyć się z bazą danych w drugiej sieci.

3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):
- Pamiętaj: W GCP podsieci (subnets) nie stanowią granicy bezpieczeństwa sieciowego. Domyślny router VPC umożliwia pełną komunikację między wszystkimi podsieciami w tej samej VPC.
- Izolację sieciową i kontrolę dostępu wewnątrz VPC realizuje się wyłącznie za pomocą VPC Firewall Rules z użyciem target/source tags lub kont usługowych (Service Accounts).

4. Reguły wyboru odpowiedzi:
- Ograniczenie komunikacji między maszynami w VPC -> Reguły Ingress Firewall z użyciem Tagów / Kont Usługowych.

5. Dodatkowe źródła:
