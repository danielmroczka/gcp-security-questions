Question 35 / 361

You are a member of the security team at an organization. Your team has a single GCP project with credit card payment processing systems alongside web applications and data processing systems. You want to reduce the scope of systems subject to PCI audit standards.
What should you do?

  • A. Use multi-factor authentication for admin access to the web application.
  • B. Use only applications certified compliant with PA-DSS.
  • C. Move the cardholder data environment into a separate GCP project.
  • D. Use VPN for all connections between your office and cloud environments.
Show Suggested Answer Hide Answer
Suggested Answer: C

Wyjaśnienie

Poprawna odpowiedź: C

1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:
Celem organizacji jest ograniczenie zakresu audytu zgodności z normą PCI DSS (PCI Audit Scope reduction). Obecnie systemy przetwarzające dane kart płatniczych (Cardholder Data Environment - CDE) działają w tym samym projekcie co inne aplikacje:
- Przeniesienie środowiska danych kart płatniczych (CDE) do oddzielnego, dedykowanego projektu GCP (C): W chmurze Google, projekt (Project) stanowi najsilniejszą granicę administracyjną, uprawnień (IAM) oraz sieciową (VPC). Izolując systemy CDE w osobnym projekcie, automatycznie wyłączamy pozostałe aplikacje i systemy z zakresu audytu PCI, co drastycznie zmniejsza koszty i stopień skomplikowania audytu.

2. Wyjaśnienie niepoprawnych odpowiedzi:
- A. Uwierzytelnianie wieloskładnikowe (MFA): Jest wymagane przez PCI DSS, ale samo w sobie nie zmniejsza zakresu audytu dla systemów znajdujących się w tym samym projekcie.
- B. Używanie tylko aplikacji PA-DSS: Zapewnia zgodność oprogramowania, ale nie wpływa na izolację infrastruktury i ograniczenie zakresu audytu sieciowego.
- D. Połączenie VPN z biurem: Zabezpiecza transmisję danych do chmury, ale nie izoluje systemów nie-PCI od systemów PCI wewnątrz chmury.

3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):
- Najbardziej skutecznym sposobem na ograniczenie zakresu audytu PCI DSS (scope reduction) jest izolacja logiczna i sieciowa (segmentacja).
- W GCP najlepszym kontenerem segmentacyjnym jest dedykowany Project z własną siecią VPC.

4. Reguły wyboru odpowiedzi:
- Ograniczenie zakresu audytu (PCI scope reduction) -> Segmentacja/Izolacja (osobny projekt GCP).

5. Dodatkowe źródła:
- PCI DSS Scoping and Segmentation: https://cloud.google.com/solutions/pci-dss#segmentation

Wyjaśnienie Audytowe

Reguła Egzaminacyjna (Exam Rule):
Pamiętaj, że w egzaminie Professional Cloud Security Engineer kluczowe jest wybieranie rozwiązań najmniej uprzywilejowanych (Principle of Least Privilege), zoptymalizowanych kosztowo i spełniających wymogi compliancy (np. CMEK, Data Loss Prevention).

Haczyki egzaminacyjne (Exam Traps):
- Wybór rozwiązań, które wydają się wygodne, ale nie spełniają wymogów bezpieczeństwa (np. zbyt szerokie uprawnienia IAM).
- Mylenie usług: np. Cloud Armor (WAF) z Cloud IAP (Identity-Aware Proxy).

Głębokie wyjaśnienie techniczne (GCP Professional Cloud Security Engineer):
W każdym pytaniu analizuj warstwy: IAM (dostęp), Encryption (at rest/in transit), Logging/Monitoring (Audit Logs, Cloud Logging, Security Command Center) oraz Networking (VPC Service Controls, Firewall Rules). GCP kładzie duży nacisk na współdzieloną odpowiedzialność (Shared Responsibility Model) - klient odpowiada za konfigurację zabezpieczeń wewnątrz usług chmurowych.
