Question 37 / 361

A company allows every employee to use Google Cloud Platform. Each department has a Google Group, with all department members as group members. If a department member creates a new project, all members of that department should automatically have read-only access to all new project resources. Members of any other department should not have access to the project. You need to configure this behavior.
What should you do to meet these requirements?

  • A. Create a Folder per department under the Organization. For each department's Folder, assign the Project Viewer role to the Google Group related to that department.
  • B. Create a Folder per department under the Organization. For each department's Folder, assign the Project Browser role to the Google Group related to that department.
  • C. Create a Project per department under the Organization. For each department's Project, assign the Project Viewer role to the Google Group related to that department.
  • D. Create a Project per department under the Organization. For each department's Project, assign the Project Browser role to the Google Group related to that department.
Show Suggested Answer Hide Answer
Suggested Answer: A

Wyjaśnienie

Poprawna odpowiedź: A

1. Kompleksowe wyjaśnienie poprawnej odpowiedzi:
Wymagane jest automatyczne przydzielanie uprawnień do odczytu (read-only) wszystkim członkom danego działu do nowo tworzonych przez nich projektów, przy jednoczesnym zablokowaniu dostępu dla innych działów:
- Utworzenie folderu dla każdego działu pod Organizacją i przypisanie roli Project Viewer (Przeglądający projekt) odpowiedniej grupie Google Group powiązanej z danym działem na poziomie tego folderu (A): Dzięki hierarchii zasobów w GCP, uprawnienia nadane na poziomie folderu są automatycznie dziedziczone przez wszystkie projekty w nim utworzone. Gdy członek działu utworzy nowy projekt wewnątrz przypisanego folderu, cała jego grupa działowa natychmiast otrzyma do niego dostęp jako Project Viewer, a projekty innych folderów pozostaną dla nich niewidoczne.

2. Wyjaśnienie niepoprawnych odpowiedzi:
- B. Rola Project Browser na poziomie folderu: Rola `roles/browser` pozwala jedynie na przeglądanie struktury projektów (ich nazw i identyfikatorów) w hierarchii, ale nie daje uprawnień do odczytu zasobów wewnątrz projektu (np. wyświetlenia maszyn VM, baz danych), co jest wymagane.
- C. Przypisanie roli Project Viewer na poziomie Projektu: Zmuszałoby to użytkowników do ręcznego nadawania uprawnień przy każdym nowo utworzonym projekcie, co wyklucza automatyzację i jest podatne na błędy ludzkie.
- D. Rola Project Browser na poziomie Projektu: Podobnie jak w C i B, nie zapewnia automatyzacji dziedziczenia i nie daje praw do odczytu zasobów wewnątrz projektu.

3. Wskazówki i pułapki egzaminacyjne (Tips & Tricks):
- Do automatycznego i spójnego przydzielania uprawnień dla nowo tworzonych projektów zawsze wykorzystuje się dziedziczenie IAM na poziomie Folderu.
- Rola Project Viewer pozwala na odczyt zasobów, rola Project Browser to minimalna rola pozwalająca jedynie widzieć projekt na liście (nie daje wglądu w zasoby).

4. Reguły wyboru odpowiedzi:
- Automatyczne uprawnienia dla nowych projektów grupy -> Rola Project Viewer nadana na poziomie Folderu.

5. Dodatkowe źródła:
- IAM Inheritance: https://cloud.google.com/iam/docs/resource-hierarchy-access-control

Wyjaśnienie Audytowe

Reguła Egzaminacyjna (Exam Rule):
Pamiętaj, że w egzaminie Professional Cloud Security Engineer kluczowe jest wybieranie rozwiązań najmniej uprzywilejowanych (Principle of Least Privilege), zoptymalizowanych kosztowo i spełniających wymogi compliancy (np. CMEK, Data Loss Prevention).

Haczyki egzaminacyjne (Exam Traps):
- Wybór rozwiązań, które wydają się wygodne, ale nie spełniają wymogów bezpieczeństwa (np. zbyt szerokie uprawnienia IAM).
- Mylenie usług: np. Cloud Armor (WAF) z Cloud IAP (Identity-Aware Proxy).

Głębokie wyjaśnienie techniczne (GCP Professional Cloud Security Engineer):
W każdym pytaniu analizuj warstwy: IAM (dostęp), Encryption (at rest/in transit), Logging/Monitoring (Audit Logs, Cloud Logging, Security Command Center) oraz Networking (VPC Service Controls, Firewall Rules). GCP kładzie duży nacisk na współdzieloną odpowiedzialność (Shared Responsibility Model) - klient odpowiada za konfigurację zabezpieczeń wewnątrz usług chmurowych.
